## 二、交互键解耦（问题 1 / 5）

### 目标键位（围绕 WASD，全部单手可达）

| 键 | 语义 | 现有映射 |
|---|---|---|
| **E** | 通用交互：维修 / 搜尸 / 领申请单 / 圆桌 / 门 | 现在是"所有交互" |
| **F** | 设施交互：电闸 / 监控 / 供电面板 | 无 |
| **Q** | 异形专用：钻管道 | 无（现在混在 E 的多项里） |
| **R** | 报告尸体 | 现在死亡后是"重开" |
| **G** | 拖尸 / 放下 | 无 |
| **V** | 供电面板开关 | 已有（面板内 V/ESC 退出） |
| **Tab** | 任务 / 地图 / 身份卡 | 无 |
| **1-9** | 同点多目标时按序号直选 | 已有但无提示 |
| **左键 / 右键** | 出刀（异形）/ 开枪（人类） | 已有 |
| **Esc** | 只做"释放/收回鼠标 + 关闭最上层面板"，**永不退出游戏** | 现在分支过多 |
| **F2** | DEV | 已有 |

### 实施要点

1. **建 InputMap**：在 `project.godot` 声明 `interact / facility / pipe / report / drag / power / tasks` 七个 action，代码里只读 action，不再散落 `KEY_E` 字面量。这样以后改键不用改代码。
2. **交互项按类别归位**：`_collect_offers()` 给每个 offer 加 `slot: "interact"|"facility"|"pipe"|"report"`，`_update_interaction` 按当前按键过滤后显示提示。E 永远只吃 `interact`，管道只吃 Q。
3. **同点多目标**：同一 slot 下仍可能有 2~3 项（如两个设备挨着）——这时**按 1/2/3 直选**，提示写成 `[E] 1 维修配电箱 · 2 搜尸`，不再弹轮盘。
4. **轮盘只作为兜底**：保留 `ui_wheel`，但改成**环形 8 扇区、屏幕中心、半透明**，且打开时在准星下方显示"松开取消 / 点击或按 1-9 选择"。触发方式改为**长按对应键 0.25 s**（短按=直接执行唯一项）。
5. **ESC 收口**：所有"用 ESC 关闭"的分支改为统一走 `_close_topmost()`，只关 UI，不改游戏状态、不重开、不退出；`Esc` 不再参与任何"退出到开始页"（那个只留设置面板里的按钮）。

**范围**：`main.gd` 输入段（约 7180-7270）、`_update_interaction`（5797-5870）、`ui_wheel.gd` 重写（121 → 约 260 行）、`project.godot` 加 InputMap。**风险**：中（输入是主链路，需要逐项回归）。

## 三、管道（问题 2）

**根因**：管道入口用 `role`（开始页字符串）判断，而不是 `sim.me().alien`。两个来源一旦不一致，异形就没有管道入口。

**方案**：

1. 判定统一改为 `sim.me()` 的 `alien` 字段（与 AI 同源）；`role` 只用于 UI 文案。
2. 管道项单独占 **Q**（不再混进 E 的候选），只要站在管道口 2.0 m 内且是异形就常亮提示。
3. 管道口加**发光环 + 房间色**（`space.json` 里有 `pipe_tint`，10 个房间各一色），让玩家知道"这里有入口"——现在完全没有视觉标识。
4. 进管道后给 0.3 s 黑屏过渡 + 落点音效，避免"瞬移"的错觉（现在直接改坐标）。

**验证**：`--interacttest` 里已有"异形 N / 人类 0"的断言（`main.gd:3284`），补一条"从管道口按 Q 必须打开出口列表"。

## 四、出刀判定与同质化（问题 6 / 7 / 8）

### 4.1 刀不到的几何 bug（优先修）

现状：
```gdscript
var p3 := Vector3(ap.x, 1.0, ap.y)      # 目标点固定 1.0 m
var to := p3 - eye                       # eye 在 1.62 m
var dot := fwd.dot(to / d)               # 含垂直分量
if dot > 0.55 ...                        # 贴身时必然失败
```
修法：
- 点积**只算水平面**：`Vector2(fwd.x, fwd.z).dot(Vector2(to.x, to.z).normalized())`，阈值降到 0.35（约 ±69° 锥）。
- 距离判定用**两者脚点水平距离**，与 AI 完全一致。
- 贴身保护：水平距离 < 0.45 m 直接视为命中（不用看点积）。
- 刀程从 1.35 调到 **1.55**（略放宽，抵消 sim 位置与画面 12 Hz 插值的偏差），并在 `space.json` 单点改，两仓同步。

### 4.2 玩家与 AI 同质

现状差异：

| 项 | 玩家 | AI |
|---|---|---|
| 目标选择 | `_aim_target`：距离 + 视野锥 0.55 | `ai_alien`：只判距离（`real_d <= reach`） |
| 阵营过滤 | **无**（全阵营可刀） | **无** |
| 开枪阵营过滤 | 无 | 无 |
| 冷却 | 1.2 s | 无（每夜 1 把） |

方案：把"能否出刀"抽成 sim 的单一函数
```gdscript
func can_knife(killer_i: int, victim_i: int) -> Dictionary
# 返回 {ok: bool, reason: "faction"|"reach"|"los"|"no_knife"|"downed"}
```
玩家与 AI 都调它，**判定逻辑只此一处**；玩家侧只额外做"准星指向"筛选（这是操作方式差异，不是规则差异）。

### 4.3 阵营规则显式化

- 出刀：**2.5D 无阵营限制**（`js/game.js:4226` 只判刀数/目标存活未倒地）；3D 的 `if v.alien` 必须删。
- 开枪：**当前不禁止**，人类可以打同伴、异形可以打异形。
- 建议：把 `friendly_fire_knife: false` / `friendly_fire_gun: true` 写进 `space.json`，两端同读；UI 上给出明确反馈（"同阵营，刀不收" / "打中同伴 · 记危险行为"）。

> 需要你拍板：**开枪是否允许误伤同伴**？现在是可以的，但没有任何提示，玩家会以为是 bug。

## 五、DEV 透视与身份（问题 4）

### 现状
`F2` → 右侧 15 行常驻面板，占屏幕右侧约 1/3，且只显示状态文字，没有空间信息。

### 目标（FPS 式 ESP）
1. **去掉常驻面板**，改为屏幕空间覆盖层（CanvasLayer + `_draw`）：
   - 每个活人画一个**方框**（用 `camera.unproject_position()` 把 3D 头顶/脚底投到 2D）；
   - 框上方写 `名字 · 异形/人类 · 距离 m · 当前动作`；
   - 穿墙可见（不判遮挡），颜色：异形红、人类青、濒死橙、尸体灰；
   - 距离 > 25 m 不画，避免糊成一片。
2. **DEV 时投票界面显示真实身份**：会议面板每行加 `[异形]` / `[人类]` 标签（仅 `sim.dev` 或 `sim.spectator` 时渲染）。
3. **尸体卡显示凶手**（现在只有 DEV 日志里有）。
4. 保留 `F3` 打开旧的文字总览（给调试用，默认隐藏）。

**范围**：新增 `_draw_dev_esp()`（约 120 行）+ 会议面板一行改动 + `dev_panel` 默认隐藏。**风险**：低（只读 sim，不影响判定）。

## 六、E ≠ ESC（问题 5）

### 现状
ESC 有 5 个独立处理点：`ui_panels` 打开、`_info_open`、`_pipe_open`、自由游玩释放鼠标、轮盘取消。E 没有任何事件级处理，只有每帧轮询 `Input.is_physical_key_pressed(KEY_E)`。

### 待复现
需要在实机上确认"按 E 退出"到底是哪一种：
- (a) 打开某个面板后按 E 被当成 ESC 关掉；
- (b) 按 E 打开了设置面板的"退出到开始页"；
- (c) 按 E 让鼠标从 CAPTURED 变 VISIBLE，看起来像"退出"。

### 方案（无论哪种都能覆盖）
1. **输入埋点**：给 `_unhandled_input` 加一个 `--inputlog` 开关，每次按键打印 `keycode / physical_keycode / scancode / 当前 UI 状态`，跑一次就能定位。
2. **状态机收口**：定义 `UI_STATE = {PLAY, WHEEL, PIPE, PANEL, MEETING, INFO}`，任何按键先过状态机再分发；同一帧内**打开 UI 的那个键不允许在同一帧关闭它**（用 `_opened_frame` 比对）。
3. **ESC 单一出口**：只保留"关闭最上层 UI / 释放鼠标"，删除其余分支对 ESC 的解释。
4. **退出游戏只保留一个入口**：设置面板里的按钮，且需要二次确认。

## 七、人类持枪（问题 3）

- 现状：右键开枪，无 viewmodel、无枪口火光、无后坐力。
- 方案：
  1. **程序化枪模型**（同刀的做法）：枪身 + 握把 + 弹匣 + 准星，挂在相机右下；人类且有子弹时显示。
  2. **贴图用千问出**：`gun-body`（发黑钢件）、`gun-grip`（聚合物防滑），沿用 `gen-qwen-materials.ps1` 加两条 prompt，512² 约 47 s/张。
  3. **开火表现**：0.06 s 后坐力（位置 + 旋转回弹）、枪口闪光（OmniLight3D 闪 40 ms + 小面片）、弹壳粒子、命中时复用刀的命中标记与红闪（换成白色准星反馈）。
  4. 子弹耗尽 → 枪收起、提示"去军械库领子弹"。
- **范围**：`player.gd` +180 行、`main.gd` 开火回调 +40 行、2 张千问贴图。**风险**：中（新几何可能与墙体穿插，需要 near clip 调整）。

## 八、"贴图直接贴身上"的说明（问题 9）

你说的做法就是**现在这一版**：4 个材质槽各挂一张平铺贴图，骨骼照常驱动 `idle/walk/knife/down`，没有做任何高模。

看起来"不够贴"的原因是 **UV**：模型是盒子拼的，每个面 UV 都是 0..1，贴图被拉伸到面的大小，所以胸口和腿上的布纹密度不一样。

两条路，任选：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 保持现状** | 继续平铺，按面大小手调 `uv1_scale` 分槽 | 零成本 | 只能近似，近看仍有拉伸 |
| **B. 三平面投影（推荐）** | 写一个 `shader_type spatial` 的 triplanar 材质，按**物体空间坐标**投影贴图，完全不要 UV | 不拉伸、不用改模型、不用 Blender | 骨骼形变处会有轻微"流动"，需要调缩放 |
| C. 正式 UV 展开 | Blender 展开 + 烘焙图集 + 法线 | 最接近成品 | 要动模型资产，工时最大 |

B 最符合你说的"直接把衣服贴身上、只让骨骼动"，而且不碰模型文件。**建议先做 B**，如果还不满意再上 C。
