# 玩家视角双版本调研报告（2026-11-12）

> 调研方式：分别以 2.5D 与 3D 的**玩家身份**进局，用真实键鼠走完可触达的操作链，
> 每步留截图与状态读数；再把「按下去没反应 / 反应和预期不符 / 两版不一致」逐条回到代码定位。
> 不是跑自测：自测断言的是「函数被调到」，本报告记录的是「玩家看到什么、以为什么、实际发生什么」。

## 1. 调研方法与边界

| 项 | 2.5D | 3D |
|---|---|---|
| 运行形态 | Chrome/Edge 打开 `index.html`（真实入口，含开局会议） | Godot 4.6 窗口 1280×720，`--role human` 快速开局 |
| 输入方式 | Playwright 真实键盘 `keyboard.press` + 鼠标 `mouse.click` | `Input.parse_input_event` 注入 `InputEventKey`/`MouseButton`/`MouseMotion`（与物理键同一条 InputMap → `_input` 链路） |
| 观察手段 | 截图 + `SKV3._t.G()` 只读状态 + `G.msg`（toast 是 canvas 文本） | 内置 `get_viewport().get_texture().get_image().save_png()` + 结构化 `STUDY` 日志 |
| 场景注入 | 3 处：脚边尸体、濒死伤员、异形身份（只为把真实按键送进需要前置条件的分支） | 2 处：脚边尸体 + 濒死伤员 + 异形标记 |
| 帧率影响 | headless 长时空转会掉到 ~0.55× 速度，站桩等待按实际比例放大 | 21–46 FPS（注入环境，不代表真机） |

截图目录（2026-11-12 已移入素材层）：2.5D 在 `%USERPROFILE%\Documents\returnlog_assets\screenshots\player-study-20261112\2d-*.png`；3D 在 `%USERPROFILE%\Documents\returnlog_assets\screenshots\3d-preview\study\3d-*.png`。
2.5D 旅程日志：`2d-journey.json` / `2d-journey2.json` / `2d-journey3.json`（同目录）。

**必须说明的两点边界**：
1. 3D 的键盘注入是**引擎级真实输入事件**，不是 OS 级 `SendInput`；它经过完整 InputMap 与 `_input`，但没有经历窗口焦点/系统键位布局。
2. 2.5D 的"真人模式"会为所有站桩动作弹小游戏遮罩；为验证站桩结算，另跑了一轮 `?test`（项目自己的"不弹遮罩"口径），两者对照写在第 4 节。

## 2. 2.5D 玩家旅程实录

### 2.1 开始页 → 开局会议
角色卡四种：人类 / 异形 / 旁观者 / 设计者，描述明确（人类"做任务推维修进度 · 搜尸取证 · 会议上投票 26 个任务点"）。选人类后进局，第一件事不是走动，而是 **50 秒开局公开讨论**：左侧发言+快捷留言、中间倒计时+「跳过讨论」、右侧 15 人投票盘，夜钟冻结在 75s。
截图：`2d-01-home.png`、`2d-02-human-selected.png`、`2d-03-meeting.png`。

### 2.2 基础按键：每个键都有中文反馈
| 按键 | toast 实际文案 | 判定 |
|---|---|---|
| W 交互 | 这里没有你能做的事 | 无交互项时明确告知，不弹空轮盘 |
| A 出刀 | 人类没有刀：按 B 开枪 | 角色差异讲清楚，还顺手教了正确键 |
| S 搜尸 | 附近没有尸体或伤者 | ✓ |
| D 收尸 | 附近没有尸体或伤者 | ✓ |
| F 施救 | 没有医疗包 | ✓ |
| R 报告 | 附近没有可报告的发现（2.4 格内）—— 同一具尸体跨夜可重报… | 规则解释到位 |
| B 开枪 | 没有子弹 | ✓ |
| H 破坏 | 你做不到 | 偏抽象，但没静默 |
| M 静音 | 音效：关 | ✓ |
| T 视野 | 视野：全亮（审计用） | ✓ |
| C 相机 | 相机：全图 / 跟随（近景） | ✓ |
| V 监控 | 要走到监控室才能调取画面 | ✓ |

截图：`2d-05-knife.png`、`2d-06-fog-on.png`、`2d-07-cam-map.png`、`2d-08-cams.png`、`2d-09-paused.png`。

**鼠标点击寻路**：点画面右下 140,90 像素，玩家移动 2.39 格。这是 2.5D 唯一的移动方式（没有 WASD）。

### 2.3 拖尸 / 搜尸 / 施救：真实操作链
在脚边注入一具尸体后：
- `S` → **弹出「搜查」小游戏**（4 个零件拖到槽位，0/4，保底 9s），不是读秒搜完。
- `D` → 拖拽成功（`drag=0`），提示 **「拖拽 银翼 · 移动变慢，再按 G 放下」**。
- 再按 `D` → 「已放下尸体」。

截图：`2d-13-drag-start.png`、`2d-14-dragging.png`。

⚠️ **提示键位写错**：2.5D 在 2026-11-06 已移除 G 别名（`js/game.js:8028` 注释「旧别名 E / Q / X / G 与 P 已移除」），拖拽键是 D，但 toast 仍写「再按 G 放下」。底部按键条同时写着「D 收尸」——**同一屏自相矛盾**，玩家照提示按 G 会完全没反应。

### 2.4 站桩动作 = 小游戏（真人模式）
| 动作 | 真人模式 | `?test` 口径 |
|---|---|---|
| 维修任务 8s | 弹「货架校准」：把 5 层货架堆到同一条虚线（±2.5%），0/5 | 纯读秒，8s 后 `prog` 增加 |
| 搜尸 | 弹「搜查」：4 零件归位 | 读秒 |
| 拉闸 3s | 同样被遮罩接管 | 读秒 → `lightState 0→2`，toast 完整（「全船变暗…本夜第 1 次，再拉要 6 秒」） |
| 施救 5s | 同样被遮罩接管 | 读秒 |

截图：`2d-21-task-minigame.png`（货架校准）、`2d-26-blackout.png`（任务遮罩盖在拉闸现场）、`2d-34-breaker-test.png`（`?test` 拉闸完成）。

⚠️ **小游戏遮罩不拦键盘**：`2d-14-dragging.png` 里「搜查」小游戏还开着（0/4），但按 D 仍然拖尸成功，底部出现拖拽提示——世界输入穿透了遮罩。代码侧 `js/game.js:7960` 的 keydown 只对 `wheel / sabPick / pipePick / camView / meet / over / paused` 做屏蔽，**没有 `_mg`（小游戏打开）判断**。

### 2.5 设施交互
| 设施 | 真实操作 | 结果 | 判定 |
|---|---|---|---|
| 任务点 | 传送到旁 + W | 「开始维修『货架校准』7s · 玩通即完成，中途退出要重做」 | ✓ 文案与遮罩一致 |
| 圆桌 | 传送到圆桌下方 + W | **无任何反应**（`qualPending=0`） | ⚠ 见下 |
| 补给点 | 传送到旁 + W | 轮盘第一项是「医疗无人机」信息，不是领补给；选 1 得到无人机状态 | ⚠ 轮盘排序把补给挤后面 |
| 电闸 | W | 「拉闸 3s」→ `lightState 0→2` | ✓ |
| 管道 | 传送到管口 + W（异形） | 轮盘选 1 → 从 (12.2,57.2) 瞬移到监控室 (88,34)，提示「穿管道 → 监控室」 | ✓ |
| 监控台 | V | 「监控台已接入 · V / ESC 退出」→ V 关闭「已离开监控台」 | ✓ |

⚠️ **申请单没有引导**：`js/game.js:4480-4481` 只在 `progress>=3` 和 `>=5` 时各 +1 张 `qualPending`。玩家一开始走到圆桌按 W 是**完全静默**的（`collectInteractions` 里 `nearRoundTable(me) && me.qualPending>0` 才生成交互项）。HUD 只显示「申请单 0」，没有任何「先修 3 个任务」的提示。

### 2.6 会议与投票
报告尸体（R）→ 夜晚会议打开（`meet.kind='night'`），右侧 15 人投票盘 + 弃权。点 1 号席位按钮，投票生效。
截图：`2d-18-meeting-night.png`、`2d-30-vote-panel.png`、`2d-31-vote-cast.png`。

## 3. 3D 玩家旅程实录

### 3.1 进局首屏
越肩视角，顶部一条完整键位条：`WASD 移动 · E 交互 · F 任务/设施 · R 报告 · G 拖拽 · Q 管道 · V 电闸 · B 破坏 · C 监控 · 左键出刀 · 右键开枪 · F2 透视 · F3 文字总览 · Esc 关闭面板 · P 设置`。
HUD：第 1 夜 / 天亮倒计时 / 全船维修 0/45 / 我的任务 4 项 / 报告 2 / 夜会 0/2 / 存活 15/15 / 区域地图 / 中央会议室「10 路在线」。
截图：`3d-01-ingame.png`。

### 3.2 WASD 与视角
- 按住 W 40 物理帧：位置 `(27.9,34.3) → (30.6,34.2)`，**移动 2.73 m** ✓
- 鼠标相对移动 `(260,0)`：视角转动

⚠️ **快速转视角后相机穿进角色模型**：`3d-03-look.png`、`3d-07-escape.png`、`3d-08-inject-body.png`、`3d-08b-e-offers.png` 四张关键帧的背景都是一片模糊肉色（角色头部/眼部特写），玩家完全失去场景视野，只剩 HUD 和轮盘可读。这不是截图瑕疵：相机挂在角色头部附近，快速旋转时模型仍在相机前，近裁剪面没有兜住。

### 3.3 交互轮盘
- 无交互项时按 E：打开**空轮盘**，标题「选择交互 · 0 项」，底部「点击或按 1-0 直选 · ESC 取消 · 松开不执行」。
- 有尸体+伤员时按 E：轮盘 5 项——`1. 报告尸体 · 银翼`、`2. 拖走尸体 · 银翼`、`3. 拖走伤员 · 北极`、`4. 搜尸 · 银翼`、`5. 施救 · 北极`。
- ESC 能关闭轮盘（`_close_topmost()` → `wheel.cancel()`），关闭后 G 立即生效，证明没有死锁。

截图：`3d-04-key-e.png`（0 项空盘）、`3d-08b-e-offers.png`（5 项）。

⚠️ **空轮盘是无效反馈**：2.5D 在无交互项时直接 toast「这里没有你能做的事」，3D 却弹一个「0 项」的空盘，玩家要多按一次 ESC 才能继续走。

⚠️ **关闭无反馈**：轮盘关闭后 toast 仍停留在「先关闭当前面板（Esc）」，玩家无法判断 ESC 是否生效（后续 G 生效才证明关了）。

### 3.5 两版操作链对照
| 能力 | 2.5D | 3D | 差异性质 |
|---|---|---|---|
| 移动 | 鼠标点击寻路（无 WASD） | WASD + 鼠标视角 | 输入映射（允许） |
| 交互 | W（唯一/轮盘） | E（轮盘） | 输入映射（允许） |
| 出刀 | A | 左键 | 输入映射（允许） |
| 开枪 | B | 右键 | 输入映射（允许） |
| 拖尸 | D | G | 输入映射（允许） |
| 施救 | F（直达） | E → 轮盘第 5 项 | 输入映射 + 层级更深 |
| 破坏 | H | B | 输入映射（允许） |
| 监控 | V（需在监控台） | C | 输入映射（允许） |
| 电闸 | W（需在电闸旁） | V | 输入映射（允许） |
| 管道 | W（异形） | Q | 输入映射（允许） |

## 6. 修复建议（按性价比排序）

1. **P0-1 相机穿模**：给越肩相机加模型遮挡处理（近裁剪面/相机与角色间射线检测后隐藏角色，或把角色放在独立 `VisualInstance3D.layers` 用第二相机剔除）。这是唯一让 3D"看不见场景"的问题，优先级最高。
2. **P0-2 / P0-3 提示键位**：两处 toast 改成读本版输入映射常量而不是硬编码字面量，避免下次改键再错。
3. **P1-1 小游戏遮罩拦截**：`keydown` 顶部加 `if(G._mg || SKMiniGame.isOpen()) { 只允许 M / ESC-中断 }`；或在 `tickDoing` 外统一 gate。
4. **P1-3 / P1-4 空轮盘与关闭反馈**：`_on_interact` 在 `offers.is_empty()` 时直接 toast「这里没有你能做的事」；`_close_topmost()` 关闭后 toast 一行「已关闭」。
5. **P1-2 toast 优先级**：给 `toast()` 加优先级/最短驻留，环境警报不覆盖玩家主动操作反馈（至少不覆盖 0.8s 内的操作反馈）。
6. **P1-5 申请单引导**：圆桌在 `qualPending=0` 时也给一条提示「修满 3 个任务可领申请单（当前 N/3）」。
7. **P2-2 F 键语义**：要么 3D 把施救提到 F、设施改 E 轮盘，要么在 HUD 明确提示「施救在 E 轮盘第 5 项」；前者更贴近 2.5D 肌肉记忆。

## 7. 结论

两版都能玩，但"能玩"的质量差距很大：

- **2.5D 的输入反馈是完整的**：每个键都有中文结果，规则解释到位；问题集中在两处——小游戏遮罩不拦键盘、以及 toast 单通道互相覆盖。
- **3D 的输入链路是通的**（WASD/G/R/E/ESC 都真的写回了 sim），但**可读性差**：空轮盘、关闭无反馈、提示键位写错、以及最致命的相机穿模——玩家在关键交互时看不到场景。
- **跨版本一致性**上，输入映射差异本身符合 `PORTING_PROTOCOL §2`，但提示文案没有跟着各版键位走，产生了"照着提示按键反而没反应"的体验，这正是用户此前反馈的"合法按键玩不了"的同类问题。

本次调研新增的 `--study` 入口（`main.gd`）只做输入注入 + 截图 + 结构化日志，不改任何玩法参数，可保留为回归工具，也可在合并前移除。
