## 二、各分支口径

### `main` — 2.5D 主分支

- 2.5D 正式版，**唯一发布分支**；`index.html` 双击即玩，`tools/deploy-pages.cjs` 从这里发 Pages。
- 版本真源：`js/config/version.js`（`SKConfig.version`），`package.json` 的 `version` / `gameVersion` 为镜像，改版本必须同批更新。
- 目录 `3d/` 是**构建输入快照**，不代表 3D 产品版本，见第四节。

### `3d` — 3D 副分支

- 3D 工程（Godot 4.6），版本真源 `3d/version.json`（当前 `V1P-0.2` / `0.2.0`），与 2.5D 版本号**互不占号**。
- 与独立仓 `returnlog-3d` 的 `master` **同一提交**（`31e7c88`）；两边互为镜像，改动同步后应保持提交一致。
- **独立历史**：该分支 2026-11-09 从「分离 3D 版为独立工程」起家（13 个提交），与 `main` 无共同祖先，GitHub 分支图上不会显示为从 `main` 分叉。这是拆分仓的既有事实，不做历史改写。
- 不与 `main` 合并；3D 客户端脚本 / 场景 / `project.godot` 不进 `main`。

### `form-ui-original` — 表单式长期副分支

- 表单式原版（`V1preview`），保留价值在**设计参照**：证据链结构、发言模板、`SKTrait` 性格轴与效用函数的原始形态。
- 长期保留，不发布、不跟随主线升版；如需查阅历史实现从这里取。

### `过渡版` — 已归档

- 2026-10-28 的过渡壳（`V2preview`，V3 规则壳 + 报告 / 投票流程 + 素材接入）。
- **状态：已归档**，只读保留，不再接受新提交；仅作历史对照，遗产设计口径见 `README.md` §关于「继承」。
- 保留而非删除的原因：它是 2.5D 重构前的最后一版可运行形态，删掉会丢失「表单式 → 实时对抗」的中间证据。

## 四、为什么 `main` 里还留着 `3d/`（2,037 个文件 / 240.38 MB）

`main` 的 `js/` 与 `index.html` 对 `3d/` **零引用**（不是运行时依赖），但构建与门禁仍在用：

| 依赖方 | 用途 |
|---|---|
| `tools/asset-guard.cjs`、`tools/assets-check.cjs` | 体积 / 清单门禁扫描 `3d/` |
| `tools/ship-layout-plan.json`（208 处）、`ship-layout-build.cjs`、`ship-layout-spec.cjs`、`ship-layout-check.cjs` | 舰船布局规格生成与校验 |
| `tools/blender-ship.py`、`tools/patch-qwen-policy.py` | 建模 / 贴图烘焙与策略补丁 |

因此**暂不移除**：直接删会让 `npm run guard` 与布局校验失败。要瘦 `main` 须先把这批依赖改为从 `3d` 分支取或迁到独立目录，属单独重构项，需单独立项与验收。

## 五、运维约定

1. **3D 改动不进 `main`**：客户端脚本、场景、`project.godot` 只落 `3d` 分支（及 `returnlog-3d`）。
2. **主线只推 `main`**：`3d` 与 `form-ui-original` 按需同步，不做「一次提交推全部分支」。
3. **归档分支不动**：`过渡版` 不再接收提交；需要复活时从标签或本地分支取，另开新分支。
4. **分支增删须确认**：删除 / 重命名远端分支前须经用户确认，并在 `CHANGELOG.md` 记录（对应红线「未确认不得删除资产与历史」）。
5. **同名 tag 注意**：仓内存在 `v1-preview` 标签（`88010b5`），与已删除的 `v1-preview` 分支同名历史遗留；引用分支时必须写完整 `refs/heads/...`。
