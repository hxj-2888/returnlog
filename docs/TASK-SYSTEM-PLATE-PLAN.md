# 方案 · 任务系统改造（Plate Task / 图上作业）

> **状态**：提案已进入实施（2026-11-19）；P1 竖切「弹药清点 + supply-ammo + tap」已落地并自测 12/0。
> **范围**：26 个任务点、14 种小游戏玩法、贴图与门禁
> **用户口径**（本次原话）：
> 「不要有那种记忆型的任务了」「分别做成不同的点按或者长按任务」
> 「需要结合现有贴图就跟电路维修一样」「我对目前的任务系统非常不满意」
> **真源纪律**：图内要素板只放 `js/data/plates.js`（AGENTS 红线 7）；任务配置只放 `js/t2/minigame.js#TASKS`；
> 本文只做设计与批次说明，不复制数值。

---

## 0. 一句话

把所有任务统一成**一张贴图 + 几个热点 + 一个动作**：
玩家在图上点、按、拖，破损/污渍/断电的区域随动作**在原图里**恢复；
不再画图外的滑条、翻牌、键盘，也不再考记忆。

## 2. 诊断（为什么现在不好玩）

| # | 问题 | 具体表现 |
|---:|---|---|
| D1 | **图是背景，不是对象** | 玩家看的是卡片中间一堆 DOM 方块/滑条，贴图被虚化压暗当背景 |
| D2 | **记忆冒充难度** | 翻牌、记顺序、抄编号 —— 难在"记住"，不在"操作" |
| D3 | **动作同质** | 4 个 place、3 个 sort、3 个 sequence、3 个 code，手感大同小异 |
| D4 | **没有重量感** | 14 种玩法里只有 `lever` 一个用长按；其余都是一次点击或一次拖拽 |
| D5 | **反馈不在图上** | 进度条在标题栏，图本身不变；玩家不知道自己"修好了什么" |
| D6 | **任务与舱室脱节** | 同一张 DOM 卡片可以出现在任何舱室，玩家感觉不到"我在配电室" |

## 3. 设计目标与硬约束

1. **零记忆**：所有线索常驻可见，不需要记住任何顺序、图案、编号（R4.5 的延伸）。
2. **图内作业**：交互热点必须落在贴图上；图外只允许标题、提示、进度三行 HUD。
3. **只有点按与长按**：拖拽视为"按住 + 移动"，不引入手势、划线、双指。
4. **每个任务手感不同**：动词 × 热点布局 × 次数 × 皮肤，四者至少两项不同。
5. **难度只靠重复次数**：沿用 R4.5，不收窄容差、不缩短窗口、不藏线索。
6. **可降级**：贴图加载失败时退回现有的 `buildWireClassic` 等价方案，`file://` 仍可玩。
7. **模块边界**：板数据只放 `js/data/plates.js`；新引擎单独成 `js/t2/plate-task.js`；
   `minigame.js` 只留 TASKS 与调度（红线 7）。
8. **与行为系统的接口不变**：小游戏只改交互层；完成 / 中断 / 放弃仍走
   `finishDoing` 与现有的 `deedEmit`（见 `docs/AI-DEED-SPEECH-PLAN.md`），
   所以"看见他做完任务 / 他做一半跑了"的目击与发言链路不受本方案影响。

## 4. 新框架：Plate + 6 动词 + 3 皮肤

### 4.1 双层贴图与「损伤遮罩」

复用 `buildPlate` 已验证的机制，把它从"接线专用"提升为**通用引擎**：

```
底层  <use class="plate-under">  同一张图，filter: blur(7px) brightness(.34)
面层  <use class="plate-face">   同一张图，mask 在未完成的热点上挖洞
```

- 未完成的热点 = 面层被挖掉 → 玩家看到的是**模糊发暗的同一张图**（像破损/污渍/断电）。
- 完成一个热点 = 把该洞缩到 0 → **原图像素自己长回来**（修好/擦净/通电）。
- 全程不新增任何图形，只改遮罩；这就是电路维修"原图长回来"的手感。

### 4.2 六个动词

| 动词 | 操作 | 反馈 | 适用 | 难度旋钮 |
|---|---|---|---|---|
| `tap` | 点一下热点 | 热点闪一下、洞缩小、计数 +1 | 取芯/插芯、锁扣、逐颗清点 | 热点数、干扰项 |
| `tapSeq` | 按图上**常驻编号**依次点 | 编号勾选、洞依次缩小 | 屏幕接口、灯带、按键 | 位数（3~5） |
| `hold` | 按住直到圆环充满 | 圆环 + 热点发光 + 洞随进度缩小 | 阀轮、螺栓、封条、锁扣 | 次数、单次时长（0.8~1.2s） |
| `holdBand` | 按住推进，松手落在亮带内 | 指针/液位 + 亮带常驻 | 注液、充氧、温控 | 杯数/路数；亮带宽度**不变** |
| `drag` | 按住拖到目标位 | 物件跟随、目标轮廓发光、吸附 | 接线、探针、货架、带子 | 件数、路径长度 |
| `aim` | 准星进带时点按 | 命中环、连击计数 | 靶道 | 连中次数（3→4）；窗口**不变** |

> 说明：`tapSeq` 的编号**画在图上**（热点角标），不是另起一行符号；
> 玩家不需要记顺序，只需要按 1→2→3 点。这就是"零记忆"的实现方式。

### 4.3 三种皮肤

同一套遮罩，三种"未完成"的视觉：

| 皮肤 | 底层滤镜 | 适用任务 | 完成时 |
|---|---|---|---|
| `cut` 破损 | `blur(7px) brightness(.34)` | 接线、换芯、封条、阀轮 | 裂缝合拢、金属反光恢复 |
| `dirty` 污渍 | `grayscale(.7) brightness(.62)` | 餐台、后厨、药柜、消毒 | 污渍褪去、颜色恢复 |
| `off` 断电 | `grayscale(1) brightness(.4)` | 灯带、屏幕、加热管、监控 | 由灰变亮、指示灯亮起 |

### 4.4 统一的卡片结构（不变）

```
┌ 标题 · 进度 x / n ────────────────┐
│ 提示一行（常驻规则，不藏）          │
│ ┌──────────────────────────────┐ │
│ │        贴图（330×330）        │ │  ← 热点、编号、亮带都在图里
│ │   热点 / 圆环 / 拖拽轨道      │ │
│ └──────────────────────────────┘ │
│ [按住看原图]（仅 cut/dirty）       │
│ 底栏：Esc 中断 · 无时限            │
└──────────────────────────────────┘
```

## 7. 数据模型

### 7.1 `js/data/plates.js`（唯一真源，红线 7）

在现有 `plates` 上增加 `spots`，不动 `wires`：

```js
'panel-fix': {
  id, label, image, size:[768,768], crop:[268,378,284,284],
  skin: 'cut',
  wires: [...],                       // 保留：接线任务仍读它
  spots: [
    { id:'core-1', shape:'rect', x:420, y:470, w:46, h:34,
      role:'socket', order:1, reveals:'core' },
    { id:'core-2', shape:'circle', x:500, y:520, r:22,
      role:'socket', order:2, reveals:'core' }
  ]
}
```

- `shape`：`rect` / `circle` / `poly`，坐标一律图片原始像素。
- `order`：`tapSeq` 的编号，**必须画出来**（角标），不能藏在 `dataset`。
- `role`：`socket` / `latch` / `valve` / `track` / `target` / `wire`。
- `reveals`：`core` / `light` / `clean` / `seam`，决定完成时的特效。
- `skin`：`cut` / `dirty` / `off`。

### 7.2 `TASKS`（`js/t2/minigame.js`）

```js
'电路维修': { k:'plate', plate:'panel-fix', verb:'drag', n:3, rounds:2,
  skin:'cut', color:'#E0574F', hint:'...' },
'变压器换芯': { k:'plate', plate:'panel-fix', verb:'tapHold', n:3,
  hold:0.8, skin:'cut', hint:'...' }
```

- `k:'plate'` 统一入口；`verb` 决定用哪个动作处理器。
- `n` / `rounds` / `hold` / `cups` / `hits` 保留现有语义（难度只加次数）。
- 旧字段（`shapes` / `icons` / `symbols` / `code` / `clue`）随旧 builder 一起删除。

## 9. 难度模型（严格按 R4.5）

| 档 | 动作数 | 单次判据 | 保底 |
|---|---:|---|---:|
| normal | 3~5 次点/按/拖 | 与现状相同 | 10s |
| hard | 6~8 次（同型 normal 的 1.5~2 倍） | **不收紧**：亮带宽度、命中窗口、吸附半径全部不变 | 16s |
| circuit | 3 处 × 2 组 | 不变 | 20s |

硬规则：

1. **不加记忆**：不出现"先看后按""背面朝上""限时记住"。
2. **不藏线索**：编号、亮带、轮廓、清单全部常驻。
3. **不罚错**：点错只提示，不重置、不扣进度（沿用现状）。
4. **不加时限**：保底到点自动完成，不是失败倒计时。

## 12. 门禁改造

### 12.1 自动求解器

`tests/test-v3.cjs` 的 `run(label)` 现在按 `k` 分支。改为按 `verb`：

| verb | 求解动作 |
|---|---|
| `tap` | 依次点 `#mg .pspot[data-i]` |
| `tapSeq` | 按 `data-order` 顺序点 |
| `hold` | `pointerdown` → 等 `dur` → `pointerup` |
| `holdBand` | `pointerdown` → 轮询液位 → 在亮带内 `pointerup` |
| `drag` | `pointerdown` → 分 10 步 `pointermove` 到目标 → `pointerup` |
| `aim` | 等准星进带 → 点（保留现逻辑） |
| `lever` | 保留现逻辑（电闸） |

### 12.2 新增断言

1. 26 个任务全部 `k:'plate'`（电闸除外），且 `plate` 能在 `SKPlates` 里找到。
2. `TASKS` 里**不存在** `match` / `sequence` / `code` / `sort` / `place` / `sync` / `pour`。
3. 每个任务的 `spots.length >= n`（热点足够，不用复用同一热点凑数）。
4. `tapSeq` 的每个热点都有可见的 `order` 角标（DOM 里读得到文本）。
5. 每个任务在保底时长内可解完（沿用现 15s 上限）。
6. `panel-breaker` 被至少一个动作使用（不再是死资产）。
7. 旧 builder 删除后，`minigame.js` 行数 ≤ 1,236。

### 12.3 迁移期兼容

P2~P3 期间新旧并存：`k` 仍是旧值时走旧 builder；`k:'plate'` 走新引擎。
断言按"新任务必须是 plate、旧任务按白名单暂留"写，P4 收口时删白名单。
