# 移植契约（2.5D ↔ 3D）

> 2026-11-11 用户裁定：**3D 版直接沿用 2.5D**。本仓（2.5D）是规则唯一真源；
> 3D 仓是同一套规则的 3D 表现层，不得另立规则。

## 1. 本仓的职责

- `js/game.js`、`js/ai/*.js`、`js/t2/*.js` 里的判定、状态机、数值是**唯一真源**。
- 改这里的任何规则 / 数值，都必须同步 3D 仓：
  1. `cd ../新返航录 3D 版`
  2. `npm run 3d:export:space` / `3d:export:rules` / `3d:export:sim`（按改动范围）
  3. 在 `3d/spec/gameplay-parity.json` 更新对应条目
  4. `npm run audit:parity` 必须不差于预算基线
- 只改表现 / 输入、不改规则的改动，不受此限。

## 2. 允许的差异（只有三类）

1. **输入映射**：2.5D 的键位 → 3D 的鼠标左右键 / E·F·R·G·Q·V·B·C。
   目标选择仍按 2.5D 规则（刀/枪都是「最近 + LOS」，枪再加 `visibleAt`），
   **不得用准星锥之类的额外门槛**。
2. **表现层**：模型、材质、粒子、镜头、HUD。表现不得反向影响判定。
3. **性能**：预筛 / 缓存必须与逐条判定等价。

## 3. 硬禁止

- 新增计时器、阈值、阵营过滤、状态分支（例如 3D 曾自造「濒死 12 秒失血」「第二刀必死」「死亡不转幽灵」）。
- 用「3D 不好实现」为理由改规则；实现不了就标 `pending`，不要造替代规则。
- 直接改 3D 仓的基线镜像（`js/`、`assets/`、`audio/`、`tools/`）。

## 4. 审阅与门禁

3D 仓的 `docs/agent/PARITY_REPORT.md` 是逐函数对账结果（当前覆盖 385 个函数），
由 `npm run audit:parity` 生成；`--strict` 用预算制防回退。移植流程见
`新返航录 3D 版/3d/PORTING_PROTOCOL.md`。

2.5D 侧提交前自检：

- [ ] 规则改动是否已在 3D 仓映射 / 标 `pending`
- [ ] 是否跑了对应的 `3d:export:*`
- [ ] 是否在 3D 仓 `npm run audit:parity` 并确认没有变差
