## 三、最高优先待办：板图交互"不像直接操控图内内容"

**用户原话（2026-11-19 晚）**：「这个图像还需要改，因为和图片不符合，不像是直接动图片里面的内容。」

**问题本质**（已查实）：`plate-task.js` 里 tap/tapSeq/hold 类任务的完成态只是
`st.node.classList.add('done')`，而 `.pspot.done` 的 CSS **只有 `pointer-events:none`**（`js/t2/minigame.js:198`）——
点完之后**图片像素永不变化**，只剩虚线框 + 徽章的 UI 状态。只有两类例外真的动了"图里的东西"：
- `panel-fix` 的 wire：断线是**按图片坐标动态重画**的，接上即图里的线接上（这正是 2026-11-05
  用户诉求「不要在图外画线，要直接操控图里的电线」的实现）；
- drag 类：`hole`/`to` 字段让图内元件被拖走、露出缺口。

新板（jukebox / transformer）和 tapSeq 全家（含刚接线的 pipe-port-ecosys 通风叶）都不满足
"直接操控图内内容"：点音键按钮不会陷下/点亮，拆芯螺栓不会旋出，通风叶不会开合。

**建议的设计方向**（接手者与用户裁定后二选一或组合）：
1. **状态遮罩法**（改动小）：给 spot 增加"完成态图内效果"——按图片坐标在 spot 区域上叠画
   canvas 遮罩/变体（音键按下变暗+下压阴影、芯仓螺栓旋出后核心熄灭、通风叶旋转一个角度）。
   需要每板定义 done 态的绘制函数或双层图。
2. **多态贴图法**（改动大、效果最好）：每板出 2 张状态图（前/后），done 后切图层。生成成本 ×2，
   需要重跑 §14 登记 + plate-overlay 核准 + plate:build。
3. **交互改 drag 化**：把"拆芯螺栓"改成 drag 类（用现成 hole/to 机制，芯被拖出露洞）——
   transformer 天然适合；jukebox 音键则适合方案 1。

**范围注意**：这条不只新板——`panel-breaker`（消毒循环闸刀）、`shelf`（货架层）等 tapSeq/hold 板
同样只有 UI 态。若立项应一次定标准、全板执行，别只补两块新板。
