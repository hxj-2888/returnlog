## 二、必须先解决的四个耦合点

1. **闭包共享状态 `G`**：现全部函数在同一 IIFE 内直接读写 `G`。拆分后需定一个显式持有者（`SKV3.state` 或 `runtime` 暴露只读 getter），**不得让四个模块各自复制一份状态**。
2. **跨域函数调用**：如 `aiTickAlien` 读 `exposureAt`、`startChatter` 读 `susOf`、`taskThreat` 读 `SKTrait.C`。拆前先列一张「跨模块调用清单」，逐个决定走命名空间还是显式传参。
3. **`const MEET` 与 `SKSanity.MEET` 同名不同物**（game.js :4720 是局部计时器状态、sanity.js 是配置表）：拆分前先给局部状态改名，否则跨文件后极易误引用。
4. **随机流**：`tools/mc-report.md` 明确「同 seed 不等于同随机路径」，新增一次 `Math.random()` 调用会挪动整条流。拆分不得新增/删除任何随机调用；若必须动，需换 seed 各跑一批看摆动幅度，不得用单批格子差值归因。

## 三、加载清单变更（须同批改）

`index.html` 是**唯一脚本加载清单**，新增模块必须按依赖顺序插入经典 `<script>`，并同步 `README.md` 项目结构、`AGENTS.md` §一红线 2。

约束：`js/ai/sanity.js` **必须早于** `js/ai/traits.js`（traits 的 `b()` 读 `SKSanity.TRAIT_GAIN`）；新模块不得用 ES Module / `fetch()` / 动态注入；`file://` 必须仍可直接双击运行。
