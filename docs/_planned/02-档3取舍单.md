# 02 · 档 3 具体取舍单（拆 `js/game.js`）

> **状态**：`待用户裁决` · 预增层 P（与 R 一样**不入库**）· 2026-11-04
> **本单只列选项、代价与验证物，不代表动工。** 用户裁定：「先做前两档，第三档留出具体取舍单」。
> **对象**：`js/game.js` — 563,215 字节、约 10,300 行、单个 IIFE 闭包，同时承载 T2 定义、T2 执行、模拟入口、渲染、HUD、输入、音效。

## 一、为什么会有这张单

档 1/2 只做标注与真源归一，**不改变文件结构**。要把「每个名词只有一个归属位置」真正落到文件层，就得处理这块跨层闭包。但它是全项目风险最高的一处，因此不做施工序，只把取舍摆清楚。

## 三、三个方案

### 方案 A · 按三域纵向切（架构最对齐）

- 拆成 `js/t2/ai.js`（认知链 / 证据 / 推测）、`js/t2/space.js`（数值 / 相位 / 额度）、`js/t2/decision.js`（小游戏 / 会议 / 投票）、`js/runtime.js`（状态机与渲染）。
- **代价**：最高。闭包内 `G`、局部函数互相调用密集，跨域调用会变成跨文件全局引用；须重排 `index.html` 加载清单（红线 1/2）。
- **撞**：`file://` 可玩、经典 `<script>` 顺序、`sanity.js` 早于 `traits.js`、`_t` 语义、随机流顺序。
- **验证物**：全量门禁 712/0、`file://` 冒烟、回放导出、复盘页、同 seed 双跑对比（粗粒度总量可跨批，单机制次数不可）。

### 方案 B · 按技术职责横切（工程最稳）

- 拆成 `render.js` / `hud.js` / `input.js` / `audio.js` / `sim.js`，保留一个 `core.js` 持有 `G` 与全部判定。
- **代价**：中等。渲染 / HUD / 输入相对独立（已有明确分区行号），但 `core.js` 依旧是跨层巨石，**架构对齐度低**——只是把大文件变小，没让名词归域。
- **撞**：`_t` 契约、`index.html` 顺序、DOM id 双处同步（AGENTS.md 红线 9）。
- **验证物**：全量门禁 + 截图比对（`tools/screenshots/`）+ 控制台零报错。

### 方案 C · 不拆，只做「逻辑分区 + 契约化」

- 保持单文件，用分区注释固定 T2/T3 归属，把 `KIND_CRED` / `EV_W` 等定义点全部外提到 `SKSanity`（档 2 已开始），并在门禁加「T2 内不得跨域复制定义」「L4 读数不得出现在即时决策输入」等静态检查。
- **代价**：最低，可完全避开加载清单与 `_t` 风险；**但 563KB 单文件不变**，新会话 agent 的阅读成本依旧高。
- **验证物**：门禁全绿 + 静态检查脚本 + 节点标注表与文件头一致。

## 四、取舍矩阵

| 维度 | A 按域切 | B 按职责切 | C 不拆 |
|---|---|---|---|
| 架构对齐 | 高 | 低 | 中（靠标注补） |
| 破坏风险 | 极高 | 中 | 低 |
| 需改 `index.html` | 是 | 是 | 否 |
| `_t` 契约风险 | 高 | 中 | 无 |
| 随机流 / 模拟可比性 | 高风险 | 中风险 | 无变化 |
| 回滚难度 | 难 | 中 | 易 |
| 跨会话可读性 | 高 | 中 | 低 |

## 五、无论选哪个都必须先满足

1. 档 1（全量节点标注）与档 2（真源归一）**门禁全绿**，且有一份可对照的实跑读数。
2. 固定 seed 的**剧情切片清单**先定（哪些局面、断言什么），否则拆完无法归因。
3. 每组单独跑、不混组；胜率与驱逐准确率只作 ±3pp 护栏与事后记录。
4. 不动平衡数值、不新增实体 / 池 / 配额、不写公式化权重；不为凑读数改过程。
5. `index.html` 是唯一加载清单；`file://` 必须可玩；中文记录；素材署名。
