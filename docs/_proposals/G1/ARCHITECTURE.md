## 1. 坐标系（总体架构不变，后续所有章节由此派生）

1. **根是体验层（L0），不是 AI 拟人化。** L1 三域（AI 拟人化 ‖ 时空与资源预算 ‖ 玩家决策）并列、非从属。推理引擎只是拟人化的一部分，拟人化只是三支柱之一。任何「用推理遥测替另两域验收」都是越界。
2. **线型 → 树状 + 网状。** 机制属于共享枢纽，被三域多父引用；小游戏同时在三处挂父，但只有一个定义点。`definedBy` 单值 / `serves[]` 多值：**多父允许、多份定义禁止**。
3. **共五层，验收层在后方、不在上方。** L0 体验 → L1 三域 → L2 机制 → L3 执行 → **L4 验收**；L0 四维度规范性，L4 描述性。另设**层外参考层 R**（见 §2.2），不占层号、不入依赖链。
4. **决策单点 + agent 执行团队。** 用户独占 L0 与立项权；agent 少量建议 + 绝大多数执行；文档是跨会话团队契约；三道闸门保决策权归属。

**三条依赖规则**：✅ 跨批次反馈允许（须显式登记、经用户）；❌ 批内回写禁止；❌ 跨批次立项必须经用户。

## 1.2 F / N 双层判据（本版按 **N 档先行**）

用户裁定：**「最新正文优先」指执行层面与历史版本对比时以最新正文为事实准绳；但最新正文不一定是正确的。**

| 档 | 回答什么 | 依据 | 约束 |
|---|---|---|---|
| **F · 事实档** | 现在实际在跑什么、读到什么 | 最新源码与正文（历史版本只作对照，不覆盖现行） | **F 不推出 N**；现状不等于合规 |

```
L0  体验层（根）      只定义「为什么」，不定义实现

L1  三域（唯一工程大类）只定义「靠什么做到」，三域并列
      AI 拟人化  ‖  时空与资源预算  ‖  玩家决策
L2  机制层 · 共享枢纽   只定义「是什么」，每个概念唯一定义点
      —— 八机制是小类的**定义点**，不是新的工程大类（见 §3.2）
L3  执行层 · 实例       只定义「怎么做」
      小游戏、保底时长、夜会 suspend/resume、门禁断言、剧情切片、README / AGENTS / CHANGELOG …
L4  验收层 · 在后方     只记录「事后看到什么」（增量台账，非达标快照）
```

**L4 在后方不在上方**，是依赖链闭合的关键。L0 四维度回答「要什么样的体验」，L4 回答「这批之后读到什么」；读数不等于描述面本身，也不构成达标判定。

**每层验证物**：L0 设计裁定 / L1 三域声明 / L2 事实表与门禁契约 / L3 用例与剧情切片 / L4 增量台账（不写「某读数 > 0 算通过」）。

### 2.2 参考层 R（层外 · 本版新增）

> 用户裁定：**「参考层有一部分是不由新的项目文件推出来的，实际上它的内容和项目文件是不直接相关的，所以参考层也不好把它放到这四个层级里面去，这就是为什么要独立出来。」**

**独立理由（规范层）**：R 层内容**不由项目文件推出、与项目文件不直接相关**，因此不能挂进任何一层、也不能进入依赖链；否则会制造「外部材料看起来像项目定义」的假边。

| 项 | 约定（DRAFT） |
|---|---|
| 位置 | **层外旁路**：不占 L0–L4 层号，不进入 `definedBy` 依赖链，不构成第六层 |
| 容纳 | ① **实践当中发生的错误**（用户裁定范围）；② 联网搜索获取的经验；③ 社区代码参考；④ 素材引用 |
| **明确排除** | **过期快照不属于 R 层**（用户裁定）。其归属另见 D-11，暂按 L4 历史档案候选处理，待用户裁定 |
| 用途 | **仅设计师决策参考**；用户读后自行决定是否立项，agent 不得代跨 |
| 硬约束 | **不可直接写进项目文件**：不得成为 L0–L4 任一层的定义、判据、验收关联、注释论证或提交依据；不得被门禁引用；不得作为「某项改动该做」的理由 |
| 结构 | 无 `definedBy`、无 `truth`、无 `verify`；`serves[]` 只允许指向「用户决策」，不允许指向任何层内节点 |
| 与 L4 的边界 | L4 = **项目自身产出**的读数台账（由项目文件推出，可入仓、可登记为下一批立项依据）；R = **不由项目文件推出**的外部/错误材料（只供参考，不作依据）。这条「是否由项目文件推出」是两者的判据 |
| 与附录的边界 | `AGENTS.md` 附录 = 项目内部历史踩坑记录，属 L3 契约附录；R = 层外，含实践错误与外部参考 |

| 存放（✅ 已定 · 已执行） | `docs/_reference/` 已建（空目录）；`.gitignore` 已追加排除。物理在项目目录内、**git 不入库** |
| 出处（✅ 已定） | 社区代码与素材引用的**出处暂不写进项目文件**（不产生定义边，也不写「参考了某实现」） |
| 采纳（✅ 已定） | 外部经验被采纳后**不在项目正文里显示**，**只在 R 层内部做标注**（建议字段：采纳日期 / 关联裁定 / 采纳人）；不产生 L0–L4 任何定义边，也不把经验内容搬进正文 |

**已定（D-21）**：外部经验永不转化为项目正文，只在 R 层留标注。R 层与 L0–L4 之间**没有任何内容通道**，只有「用户读过 → 自行立项」这一条决策路径。

## 3. L1 三域（唯一工程大类）

| 域 | 定义（只回答「靠什么做到」） | 明确不在本域 |
|---|---|---|
| AI 拟人化 | AI 在有限信息与有限注意力下，像真人一样感知、记忆、推测、发言、犹豫、保留底牌 | 不含地图拓扑、时间预算、胜率口径 |
| 时空与资源预算 | 时间预算、任务点分布与可达性、额度、胜利条件与节奏预算 | 不是可直接拧的「平衡旋钮」 |
| 玩家决策 | 玩家面临的选择结构：进不进 / 何时进 / 结不结伴 / 弃不弃 / 信谁 | 不替玩家定义最优解 |

**边界链**：`推理引擎 ⊂ AI 拟人化 ⊂ 三支柱之一 ⊂ L1 ⊂ L0 体验层`。行为节奏、发言质感、犹豫与底牌不属于推理线；不得用推理遥测替它们验收，也不得替另两域验收。

### 3.2 分类规范（本版纠正，v1 的「架构三组」作废）

> 用户裁定：**「总体架构不变……像小游戏、事件、证据这些都是属于小类，而不应该作为总的工程大类；事件证据这些都归纳于 AI 拟人化这个分类里面。」**

- **L1 三域是唯一工程大类**；小游戏、事件与证据、相位、额度等一律是**域下小类**。
- 小类可以有**归类主父**（分类树上挂哪个域），同时保留 `serves[]` 多父引用（网状影响面）。二者不冲突：分类归属 ≠ 定义权。
- L2 仍负责**唯一定义点**（树状单一真源），但**不因「是机制」就升级为工程大类**。
- **v1 §4 提出的「状态与权限 / 认知链 / 结算」三组分类作废**，不得再作为与三域并列的大类出现。

| 域（大类） | 小类（重命名后，见 §4.2） |
|---|---|
| **AI 拟人化** | **事件与证据**（用户指定归此）、推测（带不确定度）、多解释并存、注意力与在场、可读信息边界、会议时序与传播、发言质感与行为节奏 |
| **时空与资源预算** | 相位与时间账、额度与消耗、保底时长、夜 75s 时间预算、任务点分布与可达性、胜利条件 |
| **玩家决策** | 小游戏（进不进 / 何时进 / 结不结伴 / 弃不弃）、**夜会挂起**、**站桩时长压缩**、信息不对称、投票与改票、底牌保留 |

> **归类主父已定（用户裁定）**：小游戏、夜会挂起、站桩时长压缩三者**主要归类到玩家决策**；`LENS`/`CRED` 真源仍按 §5 矩阵跨三域引用。上表给的是 `category`（分类归属），**不删除也不改写 `serves[]` 多父引用**——它们仍同时挂 AI 拟人化与时空与资源预算。分类归属 ≠ 定义权（D-16 已定）。

## 6. 节点标注 schema 与依赖规则

```text
node = {
  id, layer: L0|L1|L2|L3|L4,
  definedBy:  <单一父节点 id>,          // 树状：分解与单一真源
  serves:     [<域/机制 id>, ...],       // 网状：归属与影响（多父允许）
  category:   <L1 归类主父>,             // v2 新增：小类挂哪个域，不产生大类
  truth:      <文件#符号 或 文档#章节>,  // 唯一真源
  verify:     [<验收关联 id>, ...],
  flag:       F | N                     // v2 新增：事实档 / 规范档
}
```

**允许边**：上层定义目的 → 下层定义实现；共享机制 → 实例引用；L4 →（经用户裁定）下一批立项依据。**参考层 R 不参与上述任何一条边。**

**禁止边**：❌ 批内回写；❌ agent 自行跨批次立项；❌ 同层互相定义、跨域复制定义、L3 写 L2 概念定义、以 L4 读数替另两域验收；❌ **R 层材料写入项目文件或成为立项理由**；✅ 跨批次反馈允许且须显式登记。

**四维度不是目标函数**；任何一层不得把它们改写成可优化数值。
