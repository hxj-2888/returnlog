## 一、总体判断

AI 的**证据层**做得比大多数同规模项目扎实，**表达层**和**空间决策层**还停在"阈值 if"的水平。

| 维度 | 评分 | 说明 |
|---|---|---|
| 证据链可审计性 | ★★★★☆ | `known` / `sus` 分离、`why[]` 带时间地点、事件流只读旁路 —— 这套骨架是对的 |
| 信息隔离（不作弊） | ★★★★★ | 全程不读 `alien`、无队友表、`mates` 只能靠目击推断，这条纪律守得很干净 |
| 会议推理 | ★★☆☆☆ | 有确证/反咬/时间线对质，但**证言不传递**、台词是确定性索引、15 人一个声音 |
| 空间决策（下手点） | ★★☆☆☆ | 只看"6 格内几个人"，不看光、不看逃逸、不看视野口径 —— 见 §三 P0-1 |
| 行为效用表 | ★★★☆☆ | 结构对了，但 `chase` 是常数，把拉闸/破坏挤死了 —— 见 §三 P0-2 |
| 可调性 | ★★★★☆ | `SKTrait.C` / `SKTeam` 两层声明表是正确方向，但仍有 3 处魔法数漏在业务代码里 |

一句话：**它现在"不会作弊"，但"不太会想"**。它能正确地记住"我看见他钻管道"，却不会想"这一刀在亮房里会被 40 格外的三个人看见"。

## 二、已经做对、建议不要动的部分

1. **`known` 与 `sus` 两条通道分离**（`js/game.js:1132` / `1172`）。身份级结论只由异形专属行为写入，情绪和传闻永远进不了 `known`。这条纪律让整条推理链可以事后审计，是全局最重要的设计。
2. **AI 不读 `alien` 字段、没有队友表**（`noticeAction` 里 `if(w.alien)continue`）。`mates` 只能由亲眼目击写入 —— 这是同类游戏里最容易破的防线，这里守住了。
3. **`susCut` 反向洗清 + `justified` 开枪**（`1145` / `1252`）。有"洗清"通道的嫌疑系统才算推理，不只是记仇。
4. **效用表 + 团队量化两层**（`SKTrait.C` / `SKTeam`）。把"我做这件事值不值"和"这件事还需要我做吗"分开，是正确抽象。
5. **事件流 / 回放是只读旁路**（`logEvent` 不读写判定）。改 AI 时能拿回放复盘，这个基建省下来的调试时间远超它的实现成本。

## 三、问题清单（按严重度）

### P0-1 · 亮房里的目击被 6 格上限截断 —— AI 会当着人出刀

**位置**：`js/game.js:2198 watchersAt()` → `1194 aiCanSee(...,cap=6)`；对照 `7462 visibleAt()`

`watchersAt(a,x,y,6,...)` 把 `rad=6` 传进 `aiCanSee`，而 `aiCanSee` 的**第一句**就是：

```js
if(d>cap)return false;          // cap = 6
if(!losNow(...))return false;
if(tr&&G.lit[tr.id])return true; // 亮房整间 —— 但已经过不来了
```

也就是说，**亮房"整间可见"这条规则在 AI 侧被 6 格上限吃掉了**。而玩家侧 `visibleAt` 是：

```js
const mz=litZoneAt(me.x,me.y);
if(mz){ const tz=litZoneAt(x,y); if(tz===mz)return true; }   // 同一个亮区 → 直接可见，不看距离
```

实测各舱室对角线（`js/data/map.js`）：

| 舱室 | 矩形 | 对角线 | 6 格上限漏掉的可见距离 |
|---|---|---|---|
| 中央会议室 | 42×16 | **44.9 格** | 38.9 格 |
| 仓库 | 42×12 | **43.7 格** | 37.7 格 |
| 生态舱 | 22×15 | 26.6 格 | 20.6 格 |
| 医疗间 | 18×12 | 21.6 格 | 15.6 格 |
| 军械库 | 16×13 | 20.6 格 | 14.6 格 |
| 娱乐室 | 20×14 | 24.4 格 | 18.4 格 |
| 引擎 | 14×16 | 21.3 格 | 15.3 格 |
| 配电室 | 12×13 | 17.7 格 | 11.7 格 |
| 监控室 / 食堂 | 11×10 / 10×11 | 14.9 格 | 8.9 格 |

**10 个舱室没有一个对角线 ≤ 6 格。** 走廊更糟：c6 长 38 格、c11 长 23 格、c3 长 16 格，而亮走廊对玩家也是整条可见。

后果有三层：
- **玩法层**：异形在亮房里当着 10~40 格外的人出刀，系统认为"没人看见"，于是不写 `known`、不进入 `seenBy` —— 玩家明明看见了，AI 却完全不认。
- **公平层**：玩家是比任何 AI 都强的证人（整间可见 vs 6 格）。玩家指控时，AI 无法佐证，会议直接变成"玩家一个人咬人"。
- **平衡层**：蒙特卡洛里的出刀成功率被系统性高估（AI 不知道自己在被看），人类 43.1% 的胜率里有一部分是这么丢的。

**修法**：见 §四「出手隐蔽性」。核心是把"数人头"换成"算暴露度"，目击半径按 `litZoneAt` 的真实口径取，而不是一律 6。

### P0-2 · `chase` 是常数，把拉闸/破坏挤死了；没刀的异形整夜不拉闸

**位置**：`js/game.js:2295-2300 alienPlan()`

```js
const chase=td<SKTrait.C.knifeReach(a)?12:(td<5?9:2);   // ← 不看 a.knife
const best=Math.max(scBr,scSb,scBot,chase);
if(best<=chase)return{id:'chase',room:null,score:chase};
```

而另外三项的**上限**是死的：

| 动作 | 公式 | 理论最高分 |
|---|---|---|
| 拉闸 | `14 × left − 3 × 1.5 − walk` | 14 − 4.5 = **9.5**（`left` 取满 1、`walk` 取 0） |
| 破坏 | `8 × left − walk − 1` | **7.0** |
| 拆保安 | `13 × left − walk` | 13（但要求 `secbotRaidOk` 围攻前提） |

于是：
- **目标在 1.3~5 格内时 `chase=9` > 破坏上限 7.0** → 破坏**永远选不上**；
- **目标在 1.3 格内时 `chase=12`** → 拉闸（≤9.5）也选不上；
- **`a.knife<=0` 时 `chase` 仍然是 12/9** → `alienPlan` 永远返回 `chase`，而 `chase` 分支在下面被 `if(a._plan.id!=='chase')` 直接跳过，接着 `if(a.knife<=0){ 随机游荡 }`。

**净结果：一只刀用完的异形，只要附近 5 格内有活人，这一夜就再也不会拉闸、不会破坏，只会满船乱走。** 效用表被一个常数架空了。

**修法**（两行）：
```js
const canKill=a.knife>0;
const chase=!canKill?0:(td<SKTrait.C.knifeReach(a)?12:(td<5?9:2));
```
同时把 `SABOTAGE_VALUE` 从 8 提到 10~11，让"目标在 2~5 格"时破坏和拉闸真的有机会被选中（否则它们只在"附近没人"时才发生）。

### P0-3 · 人类 AI 修故障时不做任何威胁判断

**位置**：`js/game.js:1893-1902 aiHuman()`；`taskThreat` 只挂在 `_doing==='task'`

```js
if(a.doing>0&&a._doing==='task'){          // ← 只有 task
  const th=taskThreat(a,a.doing);
  if(th){fleeTask(a,th);return;}
}
...
if(a.doing>0){a.doing-=dt;if(a.doing<=0)finishDoing(a);return;}   // fix 走这里，无条件站满
```

`FIX_TIME=10`（`js/game.js:806`）。也就是说：**AI 会在一只已确证的异形 3 格开外走过来的时候，站着把 10 秒维修修完。** `AGENTS.md` 里写的"`fleeTask()` 在已知异形快速逼近且修不完时弃修逃跑"其实只对任务点生效，故障点没有接线。

**修法**：把 `_doing==='task'` 放宽成 `a._doing==='task'||a._doing==='fix'`，`fleeTask` 里对 fix 分支补 `dropStaleFix(a)`。

### P1-1 · 证言不进嫌疑分：一个人确证 = 一票，说服不了任何人

**位置**：`js/game.js:3560`（人类指控只写 `a.accuse`，没有任何 `susAdd` 传给听众）

全仓 `susAdd` 的 **17 个调用点**里，**没有一个是"AI 公开指控 → 听众加嫌疑"**。跨 AI 的证据传递只有两条：`heard_frame`（异形造谣，+0.14）和 `heard_claim`（玩家直接证据，+0.12~0.30）。

所以人类 AI 在会议上说出"我确定 05 是异形，我亲眼看见他出刀"时：
- 说话者自己 `known[5]` → 投 5；
- 其他人 `sus[5]` 一点不动，只有 `leadingAccused()` 让"自己本来对 5 有 ≥0.18 嫌疑"的人跟票。

**结果是"确证"这个机制在社交层几乎无效**：目击者只有自己那一票，3 票门槛靠运气。这也解释了为什么 `exiles` 只有 2.01/局。

**修法**：加一条"证言通道"，权重 = 说话者可信度 × 听众对他的信任 × 证言可核查性：
```js
/* 公开指控的可信度：手上有 known 的人说话最重；空口指控最轻（已被 empty_accuse 罚过） */
const cred=a.mind&&Object.keys(a.mind.known||{}).length?0.55:(a.suspect!=null?0.38:0.22);
for(const w of G.agents){
  if(w===a||w.alien||!w.alive||w.downed)continue;
  if(w.mind.known&&w.mind.known[a.accuse])continue;      // 已经确证，不用再听
  const rel=1+0.35*((w.mind.trust[a.i]||0)-(w.mind.grudge[a.i]||0));
  susAdd(w,a.accuse,cred*rel*0.5,'heard_accuse',ev);
}
```
注意：**只写 `sus`，绝不写 `known`** —— 这条不能破。

### P1-3 · `voteGrudgePull` 单位混用

**位置**：`js/ai/traits.js:81` 声明为「格」；`js/game.js:4731` 当概率用

```js
voteGrudgePull: a => 6 * (1 + 0.5 * b(a,'aggr')),      // 注释：附加分（格）
...
if(emo&&es>=0.6&&Math.random()<SKTrait.C.voteGrudgePull(a)/10){   // 6/10 = 0.6 概率
```

`/10` 这个魔法数就是为了把"格"掰成"概率"。行为上没错（激进 0.9 / 中性 0.6 / 谨慎 0.3），但语义是坏的：以后有人把系数从 6 调到 8，概率会静默变成 0.8 而不是"更强的拉力"。

**修法**：在 `SKTrait.C` 里新增 `voteGrudgeChance: a => Math.min(0.9, 0.60 + 0.30*b(a,'aggr'))`，`voteGrudgePull` 保留给"拉票强度"用。

### P1-4 · 异形投票纯随机，和其余"会演戏"的部分不一致

**位置**：`js/game.js:4744-4750`

```js
if(a.alien){
  const all=G.agents.filter(x=>x.alive&&x!==a&&!isMate(a,x.i));
  m.votes[a.i]=pool.length?pool[Math.floor(Math.random()*pool.length)].i:-1;
}
```

同一只异形在夜里会伪装维修、会反咬、会替队友辩护，投票时却退化成均匀随机。它**不会**做三件最自然的事：跟场上最大票数投（避免成为唯一异类）、把票压到已被冤枉的人类身上（推人出局）、避开自己已经公开辩护过的人（自相矛盾）。

**修法**（注意只能用 `a.mates` 反推，**不能读 `G.agents[lead].alien`**，那是系统身份）：
```js
if(a.alien){
  const lead=leadingAccused(a);                       // 场上票数最多的目标
  if(lead!=null&&lead!==a.i&&!isMate(a,lead)&&Math.random()<0.7){
    m.votes[a.i]=lead;continue;                       // 顺水推舟，把人类推出去
  }
  ...原来的随机兜底
}
```

## 四、异形的「出手隐蔽性判断」方案

> 这一节是**方案稿，没有落地**。等你调参跑完再决定是否接入。

### 4.1 目标

把"能不能杀"从**数人头**换成**算暴露度**，让异形的决策从
「6 格内没人 → 杀」变成「这一刀有多显眼 → 值不值得现在杀」。

### 4.2 暴露度模型

新增两个纯函数（放在 `watchersAt` 旁边，`js/game.js:2198` 之前）：

```js
/* 该点的真实目击半径：与玩家侧 visibleAt 同一口径，不再一律 6 格 */
function sightRangeAt(x,y){
  const r=roomAt(x,y);
  if(r&&G.lit[r.id])return Math.max(r.rect[2],r.rect[3])*1.15;  // 亮房整间
  if(!r&&inCorr(x,y)&&G.corrLit)return 12;                      // 亮走廊（门禁基线 12 格）
  return HUMAN_DARK_R;                                          // 暗房 / 断电 = 2.8
}
/* 暴露度 ∈ [0,1]：0 = 完全没人看得见，1 = 一群人围着看 */
function exposureAt(a,x,y){
  const R=Math.max(HUMAN_DARK_R,sightRangeAt(x,y));
  let e=0;
  for(const w of G.agents){
    if(w===a||!w.alive||w.downed||w.detained||isMate(a,w.i))continue;
    const d=Math.hypot(w.x-x,w.y-y);
    if(d>R||!losNow(w.x,w.y,x,y))continue;
    let k=1-0.70*(d/R);      // 贴脸 1.00 → 视野边缘 0.30
    if(w.doing>0)k+=0.12;    // 站桩做事的人注意力更集中
    e+=k;
  }
  /* 逃逸成本：出刀后 redT=3.0 三秒红身，离门/管道口越远越走不干净 */
  let esc=1e9;
  for(const d of (G.doors||[]))esc=Math.min(esc,Math.hypot(d.x-x,d.y-y));
  for(const q of M.pipes)esc=Math.min(esc,Math.hypot(q.x-x,q.y-y));
  e+=Math.max(0,1.6-esc/3)*0.25;
  return Math.min(1,e/2.0);
}
```

### 4.3 性格门槛（写进 `SKTrait.C`，不散在业务代码）

```js
/* 出手隐蔽性门槛：conceal = 1 - exposure 低于此值就换时机/换目标。
   基线 0.42 / 激进 0.16 / 谨慎 0.62 */
knifeConceal: a => Math.max(0.08,Math.min(0.85,
  0.42 - 0.26*b(a,'aggr') + 0.20*b(a,'caut'))),
```

### 4.4 接线点（三处）

**① 出刀闸门**（`js/game.js:2804`）—— 在原来的目击者人数判定**之前**加一层否决：

```js
const conceal=1-exposureAt(a,tgt.x,tgt.y);
const watchers=watchersAt(a,tgt.x,tgt.y,6,tgt).filter(w=>!isMate(a,w.i));
if(conceal<SKTrait.C.knifeConceal(a)||
   watchers.length>=SKTrait.C.knifeWatcherCap(a)||
   (watchers.length>=1&&Math.random()>=SKTrait.C.knifeBold(a))){
  ...放弃（写 _avoid，12 秒后重试）
}
```

**② 目标评分**（`js/game.js:2597`）—— 把布尔 `watched` 换成连续暴露度：

```js
const exp=exposureAt(a,h.x,h.y);
const s=d+exp*SKTrait.C.knifeWatcherPenalty(a)+(mateOnIt?8:0)+(busy?SKTrait.C.knifeBusyBonus(a):0);
```

**③ 换时机而不是干等**（新增，替换被删掉的 `_ambushT`）
隐蔽度不够时不要原地踱步（那条已被你否掉），而是：
- 目标在**亮房** → 记 `_avoid`，转去拉闸（断电后同一间房的暴露度从 ~1.0 掉到 ~0.1）；
- 目标在**门口/走廊** → 走管道到出口侧等他过来；
- 目标在**暗房** → 直接下手（`conceal≈1`）。

这条会让"拉闸"第一次有了真正的战术动机 —— 现在拉闸只是"视野压制 + 门禁"，改完是"**为了能杀人**"。

### 4.5 会动的门禁断言（必须先知道）

`tools/test-v3.cjs:3132-3172` 这四条是**钉在旧语义上**的，改完必须同批改：

- `3132` 1 个非队友目击者 + 冒险 → 直接出刀
- `3141` 1 个目击者 + 谨慎 → 放弃目标
- `3148` 2 个目击者 → 无论随机数都放弃
- `3155` 目击者是队友 → 照常出刀

建议：把这组用例的场景**挪进暗房**（`G.lit[room]=false`），断言"暗房里 1 个目击者仍可下手"；另加一组亮房用例断言"亮房里 10 格外的目击者也会被算进暴露度"。这样两条口径都被锁住。

### 4.6 平衡风险（必须 A/B）

- 亮房出刀被压 → **总刀数下降** → 按 `AGENTS.md` 的"刀数断崖"（≤9 刀人类胜率 90%+），人类胜率会明显上跳，可能从 43% 冲到 55%+。

## 五、补给站美术（医疗补给包 / 枪械补给包）

### 5.1 现状的三个问题

`js/game.js:6067` 的 `f.kind==='supply'` 分支，画的是：
`1.08×0.82 格的圆角矩形 + 顶部色条 + 居中大图标 + 上方 9px 无底色文字`。

1. **没有体积**：整船底图是 Blender 12° 俯角烘的（顶面 + 前立面 + 接地阴影），这一块是纯平面矩形，读起来像贴在地上的 UI 按钮。
2. **没有材质**：军械 / 医疗只差一个描边色（`#6B4E19` vs `#1F5A46`），远看都是"黑框 + 图标"。
3. **标签不可读**：`9px` 裸字直接压在危险条纹上，没有暗底（同文件的 `drawBotLabel` 早就改成深色药丸底了，这里没跟上）。

这也正是 `docs/调研报告_拉闸与AI重构_20261031.md` §三 里电闸/监控台"突兀"的同一个根因：**Canvas 手画 + 底图烘焙两套渲染并存**。区别是那两件有 Blender 模型可以退，补给站**根本没有模型**，所以只能补一张贴图。

### 5.2 方案：走 `gen-facility-sprites.py` 同一条管线

已加进 `tools/gen-facility-sprites.py` 的 `SPECS`（与 medbot / secbot / monitor / breaker 同一套 2.5D 俯视 + 白底抠图 + 接地阴影）：

| 名称 | 提示词 | token |
|---|---|---|
| `supply-ammo` | `one single ammunition crate, olive-drab steel box, brass rifle cartridges inside, amber hazard stripe` + `VIEW_TOP` + `, isolated on plain white background, dark gunmetal sci-fi prop, no shadow, no text` | **57 / 77** |
| `supply-med` | `one single closed medical supply crate, dark teal steel box, white cross stencil on lid` + `VIEW_TOP` + `, isolated on plain white background, no glow, no shadow, no text` | **49 / 77** |

`VIEW_TOP = ', isometric three-quarter top view from above, seeing the top surface'`

**token 预算是硬约束**：CLIP 只吃 77 token，超了会把尾巴整段截掉。这两条是拿 `transformers` 的 tokenizer 实测的 57 / 56。

#### 第一次出图失败的原因（值得记一笔）

首版写的是 `low open ammunition crate, ...`，结果 SDXL 直接出了一张 **2×2 四宫格**（开盖/合盖对照图），背景也不是白而是中灰 —— 亮度抠图必废。两个原因：

1. **`open` 是个"状态"词**，模型会把它理解成"给我看开和关两种形态"，于是自己拼了一张对照图；
2. **`one single` 压在长句中间**，权重被前面的材质词吃掉。

改法：`one single` 提到句首、删掉 `open`、把 `isolated on plain white background` 从尾巴挪进正文。

医疗箱踩了第二个坑：`teal-green cross emblem on lid` 让 SDXL 把**整个箱体**刷成荧光绿，而且给了个**开盖**（十字跑到盖子内侧，顶面标记消失），背景还多出一张白桌面和阴影。改法：`closed` 锁死单一状态、颜色词挪到箱体上、明确 `on the top surface`、白底短语提前。

#### 第三个坑：`grade()` 在 `cutout()` 前面，把物体一起调成了背景

白箱版本出图很成功（白箱 + 绿盖 + 顶面大白十字），但抠出来只剩绿色箱盖和底座，白色箱身整块消失。

**根因不是白色物体，是顺序错了**：`post_process` 原来是

```python
graded = grade(raw, sat, dim)     # 先调色
cut = cutout(graded)              # 再抠图
```

而 `cutout()` 的判据是 **`dist<0.35` 且 `sat<0.28`**。`grade()` 的降饱和把中饱和度物体压到
`sat<0.28` 以下（深青箱体 raw `sat≈0.25`、调色后 `sat≈0.18`），于是整块箱身符合"背景"特征，
泛洪从画外灌进去，只剩几根高对比棱线。**分割和调色是两件事，调色不该影响分割。**

已改成：`cutout(raw)` 出 mask，`grade()` 只作用于 RGB，最后拼回 alpha。

**同时**，白色物体确实是这条管线的硬边界：白箱 `dist≈0.05`、`sat≈0.01`，与白底没有轮廓对比，
任何亮度抠图都救不回来（medbot / secbot / breaker 都是深色机体，所以从来没暴露）。
所以医疗箱最终改成 **深青机体 + 白色十字模板**，跟 medbot 同一套配色（`#3FBF8C` 系），
既解决抠图，也和医疗间的青色调对齐。设计原则记一条：
**要进白底管线的贴图，主体必须比白底暗**。

第四个坑：`medical case` 这个词组**每次都出开盖图**（不管写不写 `closed`）——
模型对"急救箱"的先验就是"打开给人看里面"。换成 **`medical supply crate`** 才闭合。
另外"发光十字"会让模型给箱底加一圈绿色泛光，泛光是高饱和的，抠图会把它当物体留下
（实测在箱底糊了一块青色）。所以 `glow` 已加进 `NEG`（76 token，仍 < 77）。

第五个坑：模型爱在道具后面画一道**墙/地分界线**，一条贯穿全宽的亮带。旧实现只按面积筛
（≥ 最大块 25%），这条带面积够大就会留下来，贴到地图上等于凭空多出一条白线。
已加一条规则：**左右都顶到画边的连通域直接丢弃**。

#### 顺带修掉的负向提示词截断

`NEG` 原来是 **104 token**，长期被截到 77 —— 尾巴 `duplicated object, cropped object, cut off, noise` 从来没生效过。已按「先构图、再材质、最后画质」重排并瘦身到 **74 token**（加 `glow` 后 76），整条全部生效（`collage / contact sheet / multiple views` 现在排在最前）。四件老设施已出图，不受影响。

调色（`POST_TUNE`）：
```python
'supply-ammo': (0.44, 0.94),   # 保住黄铜的暖，否则在危险条纹地板上糊成一块灰
'supply-med' : (0.30, 1.04),   # 医疗间是亮房，dim>1 才不会被浅色地砖吃掉
```

### 5.3 顺带修掉的三个工具缺陷

1. **加载器 OOM**：`stream_safetensors_to_gpu()` 原来把整个张量读进 `bytearray` 再 `torch.frombuffer`，
   **最大的一个张量要一次拿到 1.2GB 连续内存**。本机只剩 2.5GB 空闲时直接 `MemoryError`
   （本次实跑崩在加载阶段，不是出图阶段）。已改成**分块直灌显存**（48MB 一块，块内 `copy_`
   进已分配的显存张量）：峰值内存 = 单块大小，不再随张量尺寸线性增长。
   `gen-materials.py` 里是同一份代码，同样有这个问题，**没动**（你调完参可以顺手同步）。
2. **调色污染分割**：`post_process` 改成 `cutout(raw)` 出 mask、`grade()` 只作用 RGB。
3. **墙地分界线残留**：丢弃「左右都顶到画边」的连通域。
