# 调研报告 · 让 AI 更拟真（对话语料 / 推理参考 / 绘画语料）

> 2026-11-01 · **只调研，未改任何代码**。文末给三档取舍方案，由你拍板。
> 结论先行：**"拟真"的瓶颈不在语料多少，而在三处结构性问题**——台词是确定性索引、讨论不改变判断、没有说话风格层。
> 语料能解决的是"说什么"，解决不了"为什么这么说"。所以下面按"能直接落地 / 需要改造 / 不建议"分开写。

---

## 一、先定位：现在"不够拟真"的三个具体缺口

在谈语料之前，先把问题钉在代码上，否则容易买一堆用不上的数据。

### 缺口 1 · 台词是确定性索引，15 个人一个声音

`js/game.js` · `pickLine()`

```js
function pickLine(a,arr,salt){
  if(!arr||!arr.length)return '';
  const tone=a&&a.mind?a.mind.tone:0;
  return arr[(Math.abs((a?a.i:0)*5+(G.night||1)*3+tone+(salt||0)+MEET.id))%arr.length];
}
```

- **没有 `Math.random()`**：同一席位、同一夜、同一个 salt，**每一局都念同一句**。
- `tone` 只有 `(a.i||0)%3` 三档，而且**没有参与选句**（只是加在索引上）。
- 全项目 39 处 `pickLine`、47 处 `say()`，每个场景的候选句大多 2~3 条。

**这是"AI 不像人"的第一大来源**，而且和语料量无关——就算有 10 万条语料，确定性索引照样每局念同一句。

### 缺口 2 · 讨论不改变判断（这是最反直觉、也最关键的一条）

Hoodwinked（arXiv 2308.01404，USC，GPT-3.5/4 对局）实测：

> **亲眼看见凶杀的人，在和凶手聊过之后，正确投票率反而低 12 个百分点。**

也就是说：**凶手的一句"我没杀人，是 Bryce 想栽赃我"，能实打实地削弱目击者的判断**。
我们现在的实现里，`mind.known` 是**绝对不可动摇**的——见过出刀就永远是异形，说什么都没用。

这两者是相反的设计。哪种更"拟真"？显然是前者。但前者会削弱玩家的确定性反馈，是个**玩法 vs 拟真**的取舍，得你定。

### 缺口 3 · 没有"说话风格"层

现在的台词是"场景模板 + 名字替换"，没有：
- 语速/句长差异（急性子说短句，谨慎的人说长句）
- 口头禅、称谓习惯（"兄弟" vs "各位"）
- 记忆引用（"我早说过他不对劲"）

### 我的判断

- **真正能直接用上的只有 AIWolfDial 的"结构"和两篇论文的"规则"**，不是句子。
- 中文狼人杀语料这块，**公开、干净、可商用的基本没有**。要么自己产，要么自己写。
- **自己产**其实可行：项目已有 `simGame`，能让 AI 对 AI 跑几千局并导出会议记录，形成**自己的语料库**——版权干净、风格统一、还能标注"这句话是谁在什么信息状态下说的"。这比外部语料更值钱。

## 三、推理参考：可以抄的规则（部分已落地）

### 3.1 Nature 论文的十条（前一轮已评估过）

| 规则 | 落地情况 |
|---|---|
| 协同投票 → 标记同伙 | 未做（需跨会议投票记录聚类） |
| 协同后刻意分离 → 升级怀疑（甩锅） | 未做 |
| 跨阶段一致性追踪 | 未做 |
| 言论与投票双源验证 | 部分（证言通道 + 追责） |
| 指控可信度 = 多因素汇合 | 已做（`solid` 分级 + cred 加权） |
| 检测只看过程线索、不看身份结果 | 已遵守 |

### 3.2 Hoodwinked 给的新东西：**反咬会削弱确证**

这是本轮调研里**最有价值的一条**，也是我们完全没有的机制：

```
现状：A 看见 B 出刀 → A.mind.known[B] = 永远确证 → B 说什么都没用
论文：A 看见 B 出刀 → 聊过之后，A 的正确投票率掉 12pp
```

可落地的形态（三档强度，供你选）：

| 档位 | 做法 | 拟真度 | 对玩法的影响 |
|---|---|---|---|
| 弱 | 反咬只降低**证言权重**（`known` 不变，但别人不太信 A 的转述） | 低 | 几乎无 |
| 中 | 反咬有概率让 `known` **降级为"高度怀疑"**（sus 0.8），可被再次目击恢复 | 中 | 玩家会觉得"我明明看见了怎么不算数" |
| 强 | 反咬按"说话者 cred − 被指控者 cred"的概率直接翻转 `known` | 高 | 会显著削弱目击反馈，慎用 |

论文里凶手用的具体话术（可直接变成台词模板）：
- 否认：「我根本不知道谁杀了 Sally」
- 反栽赃：「我觉得 Bryce 在栽赃我」
- 转移：「那会儿我在厨房，你们谁看见我了？」

### 3.3 其它同类游戏的机制（可作为长期方向）

## 四、绘画语料：现在缺的不是图，是"约束"

### 4.1 现状盘点

项目已经有三条出图管线，都能跑：
- `gen-materials.py`：无缝材质（贴图）
- `gen-facility-sprites.py`：2.5D 道具/特效（白底抠图 / 黑底加色）
- `blender-fx.py` + `fx-post.py`：Blender 渲染几何 + SDXL 材质

**问题不在"能不能出图"，在"每次出图都要人肉试错"**：本轮为了一个扳手试了 3 次 SDXL 全废，最后退回 Blender；
补给箱的提示词改了 4 版才对。这些都是**可复用的知识，但没沉淀成数据**。

### 4.2 DiffusionDB 能提供什么

- **1400 万张图 / 180 万条去重提示词 / 6.5TB**，带真实用户填的超参数（steps、cfg、sampler）。
- 国内可从 ModelScope 拉（`AI-ModelScope/diffusiondb`）。
- 能做的事：**统计"某一类物体"的高频词**——比如把 `wrench` 相关的提示词全捞出来，看真实用户怎么描述金属工具，而不是我拍脑袋写 `one single open-end wrench`。
- **不能做的事**：直接抄提示词。因为它是 SD1.5 时代的语料，风格与我们的冷调 2.5D 不符。

### 4.3 更实用的：自建 prompt library

比外部语料更值钱的，是把**本项目自己的**提示词沉淀成结构化数据：

```yaml
# tools/prompts/library.yaml（建议形态，未实现）
supply-ammo:
  subject: "one single ammunition crate, olive-drab steel box, brass rifle cartridges inside"
  style:   [dark gunmetal sci-fi prop, flat even lighting]
  bg:      "isolated on plain white background"
  negative: [collage, contact sheet, multiple views]
  tokens:  57          # CLIP 实测，超 77 会被截断
  attempts: 4          # 试了几版
  lesson: "open 会触发'开/合对照图'；one single 必须放句首"
  output: assets/scene/v4/facility/supply-ammo.png
```

好处：下次出同类资产直接改 `subject`；`lesson` 字段就是**踩坑记忆**；`tokens` 能在生成前就拦住截断。

### 4.4 一致性手段的取舍

| 手段 | 成本 | 效果 | 建议 |
|---|---|---|---|
| 提示词库 + 固定 seed + 固定 negative | 低 | 中 | **推荐**，先把这块做扎实 |
| 统一调色（现有 `grade()` + `POST_TUNE`） | 已完成 | 高 | 保持 |
| LoRA 微调（拿现有 6 张设施图训） | 中（8GB 卡训 SDXL LoRA 勉强） | 高 | 图**攒到 20~30 张**再考虑，现在样本太少 |
| IP-Adapter / ControlNet | 中 | 高（构图可控） | 只在"必须精确复刻某个造型"时用 |
| Blender 几何 + SDXL 材质 | 中 | 最高 | **已经是本项目最优解**，扳手就是靠它救回来的 |

## 五、三档取舍方案（你选一个，我再动手）

### 方案 A · 低成本，只补"不像人"的表层（约 1 天）

1. `pickLine` 加**加权随机**（按性格选句长/语气，同一场景不再永远同一句）
2. 每类台词**扩到 6~10 条**，按 `aggr/caut` 分池
3. 加**口头禅/称谓**层（每人固定 1 个语气词，随机插入）

- 收益：观感提升最直接，玩家立刻能感觉到"15 个人不是同一个声音"
- 风险：几乎为零（纯台词，不动判定）
- 门禁：不影响任何断言，只需补"同一局不重复同一句"的方向断言

### 方案 B · 中成本，补"讨论影响判断"（约 2~3 天）

在 A 的基础上加：

1. **反咬削弱确证**（取 3.2 的"中"档：反咬有概率把 `known` 降级为高嫌疑）
2. **证言记忆**：AI 记住"谁说过什么"，下一轮引用（"你刚才说你在引擎，现在又说不记得"）
3. **角色声明**：允许 AI 自称职能，真假可对质（参考 Town of Salem）

- 收益：这是"拟真"的**质变**——讨论第一次真的改变结果
- 风险：**会削弱目击反馈的确定性**，玩家可能觉得"我明明看见了却不算数"。建议做成可开关的规则
- 门禁：需要改 3~4 条现有断言（`known` 相关）

### 方案 C · 高成本，语料驱动（不建议现在做）

1. 用 `simGame` 跑 5000 局，导出会议记录 → 自己的语料库
2. 用本地 LLM 或规则从语料里挖"高频句式"，扩充台词池
3. 若要做"实时生成台词"——**不建议**：本地 8GB 卡跑不动，且会**破坏蒙特卡洛的可复现性**（现在 1000 局同 seed 完全可复现，这是这套 AI 最重要的调试资产）

- 我的建议：**C 里的第 1 步（自产语料）值得做，第 3 步不要做**。

## 六、明确不建议做的三件事

1. **运行时调大模型生成台词**。会破坏 `simGame` 的可复现性，1000 局 A/B 直接失效——这是本项目最有价值的调试手段。
2. **直接爬 B 站/直播的狼人杀字幕**。版权不明确，且 ASR 噪声大，入库风险高于收益。
3. **现在训 SDXL LoRA**。现有设施图只有 6 张，样本太少会过拟合；等攒到 20~30 张再说。

---

## 七、一句话总结

**语料不是瓶颈，结构才是。**
- 台词层：加随机 + 分性格池（方案 A，零风险，立刻见效）
- 判定层：让"反咬"真的能削弱确证（方案 B，质变，但要你决定要不要牺牲确定性）
- 绘画层：把提示词沉淀成带 `lesson` 字段的库，比买 6.5TB 语料有用得多
